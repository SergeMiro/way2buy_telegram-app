### Що вже дало результат

Черга «бренду немає» була **1867** карток. Виявилось, що майже всі вони бренд
**називають** — просто так, що матчер його не бачив:

* стилізований юнікод Telegram: `𝗟𝗢𝗨𝗜𝗦 𝗩𝗨𝗜𝗧𝗧𝗢N`, `𝐂𝐚𝐫𝐭𝐢𝐞𝐫`, `𝒁𝑰𝑴𝑴𝑬𝑹𝑴𝑨𝑵𝑵`;
* кириличні двійники латиниці: `Нermes` (кирилична Н), `Chanеl`, `Valentinо`,
  `BERLUTІ`, `Jimmy Choо`. Схоже, навмисно — підпис, який не пише торгову марку
  буквально, не ловлять фільтри;
* доми, яких у списку просто не було: The Row, Zegna, Berluti, Kiton, Omega,
  Patek Philippe, Alaïa, Aquazzura, Zimmermann, Balmain, Messika, Graff та інші.

Після нормалізації (`foldForMatch()`) і розширення словника до 76 домів:

```
було:  1867 у черзі
стало:  345 у черзі   (1522 закрито з підпису, 136 неправильних виправлено)
```

Тобто **фотографію треба дивитись у 345 карток, а не в 1867** — і ціна питання
впала приблизно в п'ять разів ще до першого виклику моделі.

### 1.1 [Сергій] Ключ Google Gemini API

Це єдине, що блокує третій пріоритет.

1. https://aistudio.google.com/apikey → **Create API key**.
2. Передайте його мені (або покладіть самі):
   * прод: `vercel env add GEMINI_API_KEY production` у теці проєкту;
   * локально: рядок `GEMINI_API_KEY=…` у `.env`.
3. Скажіть — і я проганяю чергу.

Скільки це коштує: 345 карток × одне фото. На `gemini-2.0-flash` це центи.
Безкоштовний тариф теж витягне — він обмежений запитами за хвилину, а не
загальною кількістю, тому скрипт іде повільно і з паузами навмисно.

Без ключа нічого не ламається: `backfillBrands()` повертає
`{ skipped: 'no GEMINI_API_KEY' }`, вітрина працює як зараз.

### 1.2 [код] Прогнати чергу — щойно буде ключ

```bash
npm run brands -- --dry          # подивитись, що саме в черзі, без викликів
npm run brands -- --limit 25     # спершу 25 і перевірити відповіді очима
npm run brands                   # решта, з паузами
```

⚠️ Жодного справжнього виклику до Gemini ще не було — код покритий тестами на
розбір відповіді й на поведінку без ключа, але не на живий API. Перший запуск —
маленький і з переглядом результату.

Планувальник (`server/scheduler.js`) і сам бере по 8 карток на тик щогодини, тож
нові пости підбиратимуться самі. Разовий скрипт потрібен лише щоб зняти залишок
одразу, а не за два тижні.

### 1.3 [код] Черга не видна в кабінеті

У «Картки з каналів» показуються перші 20 карток і кнопка «Змінити» — виправити
бренд можна, **знайти** потрібну картку не можна. Треба:

* фільтр «без бренду» / «бренд з фото» у списку;
* показувати `brand_source` біля картки, щоб було видно, чиє це слово;
* лічильник черги десь на видноті.

### 1.4 [код] Словник домів доростатиме

Магазин заводить нові марки, і кожна нова — це знову картки без бренду. Раз на
місяць варто дивитись, що накопичилось у черзі:

```sql
SELECT trim(regexp_replace(body, '(?i)(size|розмір|размер)[^\n]*', '', 'g')) AS caption,
       count(*) cards
FROM posts WHERE brand_source IS NULL AND status='published'
GROUP BY 1 ORDER BY cards DESC LIMIT 40;
```

Що бачимо там регулярно — дописуємо в `BRANDS` у `server/telegram.js`.

## 2. Знайдене принагідно і вже виправлене (для протоколу)

* **`/api/admin/report` віддавав 500 місяцями.** SQL, написаний під SQLite:
  `HAVING n<=1` за аліасом і `MAX(created_at).slice(0,10)` на об'єкті `Date`.
  Плюс у коді стояв заморожений годинник `new Date('2026-07-21…')` — «звіт за
  сьогодні» вічно звітував про один липневий вечір. Тестів на модуль не було
  взагалі; тепер є (`tests/report.test.js`).
* **Фасети каталогу виконувались 376 мс.** Карта видимості Postgres була
  протухла після імпорту ~2000 постів, і index-only scan ходив у купу за кожним
  рядком. Після `VACUUM (ANALYZE)` — 2.2 мс. Синк тепер вакуумить за собою.
* **Редагування поста в каналі не оновлювало бренд.** Оновлювались заголовок і
  текст, а бренд лишався старий — звідси картки «Gucci · сумка» під фільтром
  Saint Laurent (136 штук). Там же виявилось, що це оновлення не поважало
  `curated`: правка з кабінету мовчки затиралась редагуванням у каналі.
* **Пересинк стирав би бренд, знайдений по фото** — `excluded.brand` для таких
  карток порожній. Тепер вердикт моделі переживає синхронізацію (і `vision-none`
  теж, щоб не платити за те саме фото двічі).

## 3. Решта хвостів

### 3.1 [код] Повідомлення від бота — тільки українською

Інтерфейс говорить трьома мовами (укр/рос/англ, вибір у топбарі), а все, що
надсилає сервер — привітання з днем народження, нагадування про примірочну,
промокоди — жорстко українською. Клієнт, який відкрив застосунок російською,
отримує DM українською.

Треба: зберігати обрану мову в `customers`, і слати DM нею.

### 3.2 [код] Ціна з поста-порівняння

У стрічці трапляється картка з ціною «$1 100», зібраною з поста, де порівнюються
дві речі. Той самий клас, що й бренди: у підписі кілька чисел, парсер бере не те.

### 3.3 [рішення] Картки без жодного підпису

12 карток у черзі не мають підпису взагалі — там і читати нічого. Для них фото
єдине джерело; якщо і модель не впізнає, картка лишиться без бренду і не
потрапить у жоден фільтр. Питання: показувати такі у вітрині чи ховати?

### 3.4 [код] Колаборації

`Miumiu x New Balance` — дві марки в підписі. Зараз перемагає та, що вища в
списку (Miu Miu). Для колаборації це прийнятно, але правило випадкове: воно
залежить від порядку рядків у файлі, а не від порядку слів у підписі.
