## A. Готово и проверено запуском

- `npm install && npm run seed && npm start` — поднимается на :4010 без ошибок.
- SQLite-схема: 14 таблиц (customers, purchases, redemptions, posts, events,
  promo_codes, holidays, campaigns, notifications, ai_conversations,
  ai_messages, ai_proposals, scheduler_lock) + индексы, аддитивная миграция.

  `/api/interest`, `/api/purchases`, `/api/redeem`, `/api/discounts`,
  `/api/notifications` (+read), `/api/demo/profiles`, 10 админских
  `/api/admin/*`, `/telegram/webhook`.

  `snapshotBatch()` без N+1.
- Движок кампаний `campaigns.js`: типы birthday/holiday/vip/generic,
  аудитории, материализация промокодов с защитой от дублей.
- Мост Telegram ↔ app: публикация из админки в канал и приём `channel_post`
  в ленту.
- Фронтенд: 4 вкладки (Клуб / Стрічка / Покупки / Кабінет), анимированные
  карточки скидок 4 вариантов с countdown, кольцо лояльности, колокол
  уведомлений, формы админки. Vanilla JS, без сборки.
- Деплой на Vercel настроен (`api/index.js` + `vercel.json`).

## C. Новый функционал (не начат)

- **C1. Модель товара.** Сейчас есть только `posts` (лента). Нужны `products`:
  бренд, категория, фото[], внутренний артикул, каталог, статус. Без цены.
- **C2. Каталог в Mini App** с фильтром по бренду (Chanel / Dior / LV / Gucci /
  Dolce…) и по категории. Тапом по бренду — отфильтровано. Ноль ввода текста:
  аудитория не пользуется поиском.
- **C3. Заявка на цену.** Кнопка «Хочу цю позицію» сейчас пишет только event и
  никого не уведомляет. Нужна таблица `price_requests` с состояниями
  `new → priced → confirmed → ordered → done/cancelled`, уведомление Marina,
  ввод цены Marina, автоответ клиенту.
- **C4. Загрузка карточки оператором.** Одна форма → автопубликация в нужный
  Telegram-канал + в каталог app. Это снимает ручную раскладку по 15 каналам
  и есть главная экономия её 4 часов.
- **C5. Автообработка карточки:** шаблон описания на украинском, автотеги по
  бренду, чистка EXIF, водяной знак, дедуп по уже опубликованному.
- **C6. Роли.** Сейчас один флаг `ADMIN_TG_IDS` = полный доступ. Нужны три
  роли: `owner` (Marina — всё, включая цены и правила бонусов), `operator`
  (только загрузка карточек), `support` (Даша — только заявки и клиенты, без
  цен и без настроек).
- **C7. Фиксация покупки** и списание бонуса из интерфейса Marina, с
  пересчётом баланса и записью в `redemptions`.

## E. Блокеры продакшена

- **E1. Авторизация подделываема.** Личность берётся из query-параметра
  `?tgid=`, HMAC подписи Telegram `initData` не проверяется. Любой может
  подставить чужой tgid и увидеть чужие данные или войти в админку. Обязательно
  к исправлению до живых клиентов.
- **E2. База эфемерна.** На Vercel SQLite лежит в `/tmp` и пересоздаётся на
  каждом cold start. Для продакшена нужна постоянная БД (Neon/Postgres или
  Turso), либо long-running хост.
- **E3. Режим LIVE включается случайно.** Проверено: без файла `.env`
  приложение стартует в режиме `LIVE`, потому что в окружении машины лежит
  посторонний `TELEGRAM_BOT_TOKEN`. Риск отправки сообщений не в тот бот.
  Нужен явный `W2B_MODE=demo|live` вместо вывода режима из наличия токена.
- **E4. Нет бэкапа.** Рабочая папка проекта уже пропадала дважды, код
  восстанавливали из транскриптов сессий. Пушить после каждой сессии.
- **E5. PII.** Адрес + телефон + дата рождения живых клиентов из США. Нужны:
  отсутствие PII в логах, ограничение выдачи в API только своими данными,
  политика удаления по запросу.

## F. Порядок работ

**Итерация 1 — правила (полдня).** B1, B2, B3, B5 + тесты на бонусную
математику. После этого цифры в демо соответствуют тому, что Marina
подтвердила.

**Итерация 2 — упрощение (полдня).** B4: спрятать уровни/бейджи/стрики/
праздники за флаг. Экран должен показывать ровно два бонуса.

**Итерация 3 — ядро ценности (2–3 дня).** C1, C2, C3, C4, C5, C6, B6 —
каталог, заявка на цену, загрузка оператором, роли.

**Итерация 4 — автоматика (1–2 дня).** Step 5 + Step 6: уведомления и
планировщик, чтобы ДР-бонус приходил сам.

**Итерация 5 — продакшен-гейт (1–2 дня).** E1, E2, E3, E5 + Step 11 (тесты) +
Step 13 (аудит безопасности).

AI-агент админки (Step 7) — после всего, если вообще понадобится.

## G. Как тестировать

### Локально

```bash
git clone https://github.com/SergeMiro/way2buy_telegram-app.git way2buy-miniapp
cd way2buy-miniapp
npm install
printf 'W2B_MODE=demo\nTELEGRAM_BOT_TOKEN=\n' > .env   # иначе подхватится токен из окружения (E3)
npm run seed
npm start                                              # http://localhost:4010
```

### Smoke-проверка API

```bash
curl -s localhost:4010/api/config
curl -s localhost:4010/api/demo/profiles                       # 7 демо-клиентов
curl -s "localhost:4010/api/me?tgid=100000001"                 # профиль + лояльность
curl -s "localhost:4010/api/discounts?tgid=100000004"          # Катерина — ДР сегодня
curl -s "localhost:4010/api/notifications?tgid=100000004"      # непрочитанные
curl -s localhost:4010/api/feed
curl -s "localhost:4010/api/admin/customers?tgid=100000001"    # в демо-режиме открыто
```

Ожидаемое (проверено 31.07.2026): конфиг отдаёт каналы и шаг кешбека;
`me` для `100000001` — Олена Ковальчук, потрачено $6340, кешбек $200 начислено /
$100 доступно; `discounts` для `100000004` — промокод `BDAY-KATE-30`;
`notifications` — 1 непрочитанное про день рождения.

### Ручной прогон в UI

Открыть http://localhost:4010, переключателем демо-профилей в шапке пройти по
всем 7 клиентам и проверить 4 вкладки. Админка в демо-режиме открыта без
allowlist.

### Чего пока нельзя протестировать

- **`npm test` не существует** — автотестов нет. Вся математика бонусов сейчас
  проверяется только глазами. Первое, что надо сделать вместе с итерацией 1.
- **Начисление ДР-бонуса само не срабатывает** — планировщика нет (Step 6),
  ДР-записи попадают в базу только через сид.
- **Живой режим с реальным ботом** не проверялся: нужны `TELEGRAM_BOT_TOKEN`,
  `ADMIN_TG_IDS`, публичный HTTPS-URL и `setWebhook`.

### Что должно тестироваться после итерации 1 (обязательные кейсы)

Кешбек:
- $0 → $0 бонуса; $1999 → $0; $2000 → $100; $5999 → $200; $6000 → $300;
- $8000 → начислено $400, но **доступно $300** (потолок);
- потратил $100 при доступных $300 → доступно $200, дальнейшие $2000 снова
  дают +$100;
- отменённая покупка не начисляет бонус.

День рождения:
- ДР сегодня → бонус $50 один раз, повторный прогон не дублирует;
- ДР в прошлом году → новое начисление в этом году;
- 29 февраля — не падает.

Права:
- `support` не видит цен и правил бонусов; `operator` не видит клиентов;
- запрос без валидного `initData` → 401/403.
