## 1. Бот должен быть админом каждого канала

Telegram отдаёт боту обновления `channel_post` **только если бот — админ
канала**. Без этого дублирование «канал → Mini App» не работает: приложение
просто не увидит новые посты. `getChat` проходит и без админки (канал
публичный), поэтому проверять надо именно членство:

```bash
npm run tg -- channels
```

Вывод по каждому каналу: `адмін, може публікувати` / `бот не адмін`.
Проверено 01.08.2026: **0 из 15** — бота ещё нигде не добавили.

Как добавить: канал → *Управление каналом* → *Администраторы* → *Добавить* →
`@w2b_test_bot`. Права:

| Право | Нужно | Зачем |
|---|---|---|
| Post messages | да, если публикуем из админки | иначе приложение не сможет постить в канал |
| Edit / Delete messages | нет | |
| Остальное | нет | |

Даже с нулевыми правами админ-статус даёт боту чтение постов — это минимум,
без которого ничего не поедет.

## 2. Переменные окружения

Локально — `.env` (в `.gitignore`, в репозиторий не попадает). На хостинге —
те же ключи в панели проекта.

```bash
TELEGRAM_BOT_TOKEN=…            # от @BotFather
TELEGRAM_WEBHOOK_SECRET=…       # любая случайная строка; отсекает чужие запросы
PUBLIC_URL=https://…            # публичный HTTPS этого приложения
ADMIN_TG_IDS=…,…                # Марина, Сергій — доступ в кабинет
SUPPORT_TG_IDS=…                # Даша — получает заявки в ЛС, без кабинета
SUPPORT_USERNAME=daschamelnyk   # ссылка «написати Даші» в примерочной
W2B_DB_PATH=/data/way2buy.db    # постоянный диск (см. §4)
```

Свой Telegram id — через `@userinfobot`.

## 3. Webhook и кнопка Mini App

```bash
npm run tg -- setup https://your-app.example   # webhook + кнопка меню + /start
npm run tg -- status                            # что Telegram думает сейчас
npm run tg -- unhook                            # отключить (для локальной разработки)
```

`setup` делает три вещи: ставит webhook на `/telegram/webhook` с
`allowed_updates = channel_post, edited_channel_post, message`, вешает кнопку
«Каталог» рядом с полем ввода и регистрирует команду `/start`, которая
открывает Mini App.

Проверка после настройки: опубликовать пост в канале → он должен появиться в
каталоге приложения в течение секунды. Диагностика без публикации —
`GET /api/admin/telegram` (админский эндпоинт: бот, вебхук, статус по каналам).

## 4. Постоянная база — обязательна до реального теста

На Vercel база живёт в `/tmp` и **пересоздаётся при каждом холодном старте**:
регистрации клиентов, примерочная, заявки Даше и вся статистика популярности
исчезают. Для демо это нормально, для теста с живыми людьми — нет.

Варианты, в порядке трудозатрат:

1. **Хост с диском** (Railway / Render / Fly / любой VPS) — правок кода ноль,
   только `W2B_DB_PATH` на смонтированный том. Рекомендуемый путь.
2. **Turso** (SQLite как сервис) — замена клиента в `server/db.js`.
3. **Postgres** (Neon/Supabase) — переписывание слоя доступа к данным.
